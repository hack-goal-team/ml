# Снимок состояния текущей модели оборудования

Перед сменой `inference:current` ML deploy создаёт каталог
`/mnt/backups/inference-windows/equipment-<UTC>-<commit>/` на отдельном
смонтированном диске. Каталог доступен только root. Ошибка снимка останавливает
деплой до смены образа. Старый `inference` после копирования курсора запускается
снова; скрипт ждёт `healthy`.

Ядро модели держит rolling-окна в памяти и при старте заполняет их из `events`
за последние 72 часа. `runtime/events_cursor.json` хранит позицию чтения, а не
само окно. Поэтому снимок содержит:

| Файл | Назначение |
| --- | --- |
| `events.csv.gz` | `id`, `event_id`, `channel_id`, `ts`, `raw_value`, `is_alarm` за `[snapshot_at_utc − 72 ч, snapshot_at_utc]` |
| `future_events.csv.gz` | Строки с `ts > snapshot_at_utc`: будущие по времени события могли быть уже обработаны курсором |
| `channels.csv.gz`, `objects.csv.gz` | Справочники, из которых строятся статические признаки |
| `runtime.tar` | Весь фактический `/app/runtime`, включая курсор, из тома запущенного сервиса |
| `equipment_model.cbm`, `config.yml`, `feature_encoding.json` | Артефакты текущего образа для последующей конвертации |
| `manifest.json` | Граница времени, ID образа, имя фактического Docker volume, курсор и число строк |
| `SHA256SUMS` | Контрольные суммы всех файлов выше |

Для проверки на VPS: `sudo sh -c 'cd /mnt/backups/inference-windows/<каталог> && sha256sum -c SHA256SUMS'`.
При реконструкции сначала проверяют суммы, затем читают события в порядке
`(ts, id)` и применяют `raw_value` к каждому каналу. Дополнительные строки
`future_events.csv.gz` сверяют с `low` и `seen` сохранённого курсора. Данные
после границы снимка остаются в `events` и могут быть дочитаны от курсора.
Имя тома не предполагается заранее: скрипт берёт его из mount контейнера
`inference` и записывает в manifest.
